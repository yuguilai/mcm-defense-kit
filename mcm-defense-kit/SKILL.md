# 数学建模答辩助手（mcm-defense-kit）

把一份数学建模论文，变成一套**答辩时能直接照着念、照着查**的作战工具。

产出两样东西：

1. **11 份 Markdown 手册** —— 可按需打印、可背、可分工
2. **一个单文件 HTML 应用** —— 双击即开，手机也能用，自带搜索 / AI 问答 / 语音提问检测

---

## 一、什么时候用它

用户说了下面任何一类话，就是它：

- "我要答辩了，帮我准备一下" / "怎么应对评委提问"
- "帮我写答辩自述稿" / "评委可能会问什么"
- "我们论文用了 AI 辅助，怕被问" / "代码和论文对不上怎么办"
- "帮我做一个答辩手册 / 答辩作战台 / 答辩网站"
- 用户直接上传了数学建模论文、赛题 PDF、代码，说要做答辩材料

**赛制不限**：国赛、美赛、研赛、电工杯、五一杯、深圳杯……流程大同小异，都适用。

---

## 二、你必须先做的事：访谈

**不要拿到材料就开始写。** 材料只能告诉你"做了什么"，答辩手册真正值钱的是"怎么答"。以下信息必须问出来。

### 2.1 一次性问清（用 AskUserQuestion，最多 4 个问题）

按这个优先级打包问：

| 优先级 | 问题 | 选项示例 |
|---|---|---|
| ★★★ | 这是哪场比赛、什么形式的答辩？ | 国赛线上腾讯会议 / 美赛线上 / 线下答辩 / 只是内部演练 |
| ★★★ | 答辩时长与自述时长？ | 10+5 / 8+4 / 15+10 / 不确定 |
| ★★★ | 你希望手册按什么深度写？ | 能背的完整版 / 够用的精简版 / 只给要点提纲 |
| ★★ | 团队三人各自最怕被问什么？ | 建模手 / 编程手 / 论文手（多选） |
| ★★ | 论文里有没有"说不清"的地方？ | 代码与论文不一致 / 数据来源弱 / 模型是现成改的 / 有 AI 辅助 / 没有 |
| ★★ | 需不需要"不懂代码"的专项策略？ | 需要 / 不需要 |

> **注意**：AskUserQuestion 一次最多 4 个问题。如果信息量大，**分 2–3 轮问**，别硬塞。

### 2.2 根据材料追问（自由提问）

读完材料后，你要能回答这些问题，答不上来的就**回头问用户**：

- **核心创新是什么？**（一句话版本 + 三句话版本）
- **模型的主线是什么？** 四个小问之间有没有复用同一套框架？
- **关键数字**：最优值、最大冲突度、改进百分比、迭代次数、运行时间、数据规模
- **每个公式**：它是怎么来的？为什么用这个而不是别的？参数怎么定的？
- **代码**：主程序入口是哪个文件？跑一遍要多久？输出到哪？
- **灵敏度分析做了吗？** 换了参数结果稳不稳？
- **模型有什么不足？** 用户自己承认的局限（这个必须问到，答辩必被追问）

### 2.3 访谈的说话方式

用户可能**完全不懂代码**，也可能**看不懂自己的论文**（AI 辅助写的）。这很正常，不要评判。问的时候：

- ❌ "你的目标函数为什么用线性加权而不用层次分析法？"
- ✅ "你们为什么选了这个做法？当时是怎么考虑的？随便说，我来帮你组织语言"

问到答不上来的，就记下来，回头在手册里如实写「〔此处建议按 X 思路回答，请补充〕」。

## 三、工作流

### 阶段 1：读材料

用户会给你：赛题 PDF、论文 PDF/Word、代码文件夹、数据文件、可能还有前期的分工文档。

**必须真读**，尤其是：
- 论文的**摘要**（决定人设和主线）
- 论文的**模型假设**与**符号说明**（后面公式圣经要用）
- 每个问题的**模型建立**小节（公式来源）
- **灵敏度分析 / 模型评价**章节（评委最爱追问）
- **代码主文件**（哪怕只读开头和结尾，也要知道入口和输出）

如果材料缺失（比如没有论文只有代码），**先问用户要**，别猜。

### 阶段 2：访谈

按 §2 走。**访谈结果要落成笔记**，后面填模板全靠它。

### 阶段 3：生成 meta.json

```bash
node scripts/make-meta.js --dir <md目录> --title "<论文/赛题标题>" --team "<队名或学校>"
```

它会扫目录下的 `.md`，按内置的 11 条规则匹配文件名 → 生成规范 `meta.json`（决定 HTML 里的顺序与分组）。未匹配的文件按 `90+` 序号追加，**不会漏**。

### 阶段 4：写 11 份 Markdown

模板在 `assets/templates/content/`。**分两类处理**：

#### A 类 · 固定骨架，只填少量内容（可套用度高）

这 5 份**结构不变**，你只需要把「这队人的具体情况」填进去：

| 文件 | 你要填什么 |
|---|---|
| `01_答辩流程与准备.md` | 答辩形式、时长、平台；保留全部设备检查与环境清单 |
| `04_三人分工与准备清单.md` | 三人姓名/角色、各自负责的问题、清单勾选项 |
| `06_评委问题库.md` | **27 道通用题的骨架已给**，你补每题的具体答案（引用题干里的数字和公式） |
| `08_不懂代码的准备策略.md` | 分层话术保留；补这队的代码入口、运行方式 |
| `09_应急话术.md` | **40 行话术表已给**，只需微调称呼与队内术语 |

#### B 类 · 高度依赖赛题，必须重写

这 6 份的**内容因题而异**，模板只是格式示范：

| 文件 | 重写要点 |
|---|---|
| `00_总目录.md` | 文件清单、核心数字、一条主线、三个创新、两条不足 |
| `02_自述讲稿.md` | 逐段讲稿，**严格按时长切段**，含 `【动作提示】`、`$公式$`、末尾附删减版对照表 |
| `03_公式圣经.md` | 每个公式四问：是什么 / 为什么 / 怎么用 / 注意什么；末尾必须有**公式↔代码对照表** |
| `05_代码论文不匹配应对.md` | 按「表述不一致 / 参数不一致 / 方法不一致 / 结果不一致」四类分别配话术 |
| `07_核心数字速记卡.md` | 必背数字、分问题数字表、易混数字组、默写自测表 |
| `10_三天倒计时清单.md` | D-3 / D-2 / D-1 / D-0 逐项 checkbox |

> **判断标准**：如果一份文档里出现「X 个冲突」「周期 T=8」这类只属于本题的内容，它就必须是 B 类、必须重写。

#### 写作硬规矩

1. **能念出来**。所有"回答"栏都写成**口语**，不是书面语。写完自己念一遍，别扭就改。
2. **有数字**。每个论点后面跟一个具体数字。评委对数字敏感，对形容词不敏感。
3. **承认不足**。每份关键文档都要有"我们没做到 X"的段落。只会说优点的队伍，评委会往死里追问。
4. **公式用 `$...$`**。渲染管线只认这个。**绝对不要**用 `\(...\)` 或 `\[...\]`。
5. **表格里如果有公式且含绝对值符 `|`**，写的时候紧贴 `$` —— 例如 `$\gamma\sum(|\Delta f_i|)$`。解析器已经做了保护，但你自己也别写成 `$ a | b $` 这种。
6. **不要编造数据**。用户没给的数字，写 `〔待确认：此处应填 X，请补充〕`，让用户自己补。

### 阶段 5：构建 HTML

```bash
node scripts/build.js \
  --src <11份md所在目录> \
  --out <输出目录> \
  --title "<页面标题，如：时频冲突 · 答辩作战台>" \
  --slogan "<左上角副标题，如：D题·时频冲突>" \
  --team "<队名>"
```

一条命令内部跑三步：`make-meta` → `parse` → `bundle`。

- `--slogan` 不填时会自动从 `--title` 的第一段截取，不用纠结
- `--skip-meta` 可跳过 meta 生成（当你已经手改过 `meta.json`）

输出：`<输出目录>/index.html` —— **单文件，零外链**，可直接发微信、传网盘、拷 U 盘。

### 阶段 6：验收（**不许跳过**）

用 Playwright 或浏览器手动过一遍，逐项确认：

```
□ 11 篇文档都能点开，标题正确
□ 每一页都零 LaTeX 残留（页面里不该出现 \alpha 这种原文）
□ 每一页都零 $ 残留
□ 每一页都零 [object Object]
□ 公式该有上下标的都渲染出来了（<sup>/<sub>）
□ 问题库卡片数 = 源文件里的题数，角色芯片计数不为 0
□ 话术表按分组正常显示
□ 搜索任意一个核心词，有命中结果
□ 控制台零 pageerror / 零 console.error
□ 手机宽度（375px）下不横向溢出
□ 设置面板能打开，8 个模型预设可切换，5 个语音预设可切换
□ 左上角副标题显示的是**本题**的关键词，不是别人的
```

有任意一项不过，**回去改，不要交付**。

> **自动校验脚本**（把 `PORT` 换成你的本地端口）：
> ```bash
> node scripts/build.js --src ./handbook --out ./dist --title "X · 答辩作战台"
> cd ./dist && python3 -m http.server 8891 &
> # 然后用浏览器/Playwright 打开 http://127.0.0.1:8891 逐项过清单
> ```

## 四、HTML 应用里有什么

生成的网页是四视图结构（顶部 tab 切换）：

| 视图 | 内容 |
|---|---|
| **文档** | 11 份手册全文，左侧目录树 + 右侧正文 + 页内 TOC |
| **问题** | 问题库卡片，可按角色（建模手/编程手/论文手）和星标筛选，点开看标准回答 |
| **话术** | 应急话术分组表，现场照着念 |
| **搜索** | 全局模糊搜索，`Ctrl/Cmd + K` 唤起，跨文档/问题/话术 |

外加三个运行时功能：

- **AI 问答助手** —— 接用户自己配的大模型，现场被问到不会的，输入问题让它生成答案
- **语音识别** —— 识别评委提问，自动检测问句并提示"要不要让 AI 答"
- **设置面板** —— 模型与语音接口全部可配

### 模型配置（8 个预设 + 自定义）

全部走 **OpenAI 兼容协议**，改 Base URL + 模型名即可接任意服务商。

| 预设 | Base URL | 典型模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` / `deepseek-reasoner` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` / `gpt-4o` / `gpt-4.1` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` / `qwen-max` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` / `glm-4-flash` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` / `-32k` / `-128k` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-72B-Instruct` 等 |
| Ollama 本地 | `http://localhost:11434/v1` | `qwen2.5:7b` / `deepseek-r1:7b` |
| 自定义 | 用户自填 | 用户自填 |

### 语音识别配置（浏览器原生 + Whisper 兼容，5 个预设）

| 预设 | 说明 |
|---|---|
| 浏览器内置 | 零配置，用 `SpeechRecognition`，Chrome/Edge 可用，中文识别一般 |
| OpenAI Whisper | `https://api.openai.com/v1`，`whisper-1` |
| Groq | `https://api.groq.com/openai/v1`，`whisper-large-v3-turbo`，**快且便宜，推荐** |
| 硅基流动 | `https://api.siliconflow.cn/v1`，`FunAudioLLM/SenseVoiceSmall` |
| 本地 faster-whisper | `http://localhost:8000/v1` |
| 自定义 | 用户自填任意 OpenAI 兼容 `/audio/transcriptions` 端点 |

Whisper 模式的工作方式：`MediaRecorder` 按 `切片时长`（默认 6s）分段 → 串行 POST 到 `/audio/transcriptions` → 文本回流累加。**切片时长可调**，网络差就调大。

## 四·五、★ 数据隐私：AI 回答会发送什么

**必须让用户知情。** 生成网页上的「AI 秒答」不是本地推理，它会把材料发给**用户自己配置的那家大模型服务商**。

### 会发送什么

每次点「AI 回答」，请求体里包含：

| 内容 | 说明 |
|---|---|
| **一段 system prompt** | 由 `parse.js` 的 `buildAIContext()` 在**构建时**生成，内嵌在 HTML 里 |
| **用户这次的提问** | 就一句话 |

`buildAIContext()` 打包进 system prompt 的材料，**全部取自生成的 11 份 Markdown**：

| 注入字段 | 来源文档 | 上限 |
|---|---|---|
| `problem` | 含「赛题/题目/问题重述/审题」的文档 | 20000 字 |
| `abstract` | 含「摘要/总览/总目录/概览」的文档 | 20000 字 |
| `factsCard` | 含「速记/数字卡/核心数字/事实」的文档 | 20000 字 |
| `outline` | 含「讲稿/自述/结构」的文档 | 20000 字 |
| `defects` | 含「不匹配/口径/瑕疵/不一致」的文档 | 20000 字 |
| `numbers` | 全部文档里抽出的数字串 | 8000 字 |
| `qaHints` | 问题库每题的「考点」 | 20000 字 |
| `identity` / `rolesText` | meta.json + 总目录 + 分工文档 | 很短 |

也就是说：**网页里 AI 能看到的东西，和评委能在这份手册里看到的东西，范围是一样的** —— 都是答辩时本来就会讲出来的内容，不包含原始代码文件、不包含未写进手册的论文全文。

> ⚠️ **但要注意**：如果用户在 `03_公式圣经.md` 或 `05_代码论文不匹配应对.md` 里写了敏感的**真实数据、客户信息、未公开的算法细节**，这些会随 system prompt 一起发出去。

### 必须告知用户的三句话

在交付时明确说清：

1. **「AI 秒答」会把手册内容发给模型服务商**，服务商可能是 DeepSeek / OpenAI / 通义等，取决于用户自己怎么配
2. **密钥只存在本地浏览器的 localStorage**，不上传任何第三方；设置里有「清空密钥」按钮
3. **想完全不外传，有两个办法**：
   - 用 **Ollama 本地模型**（`http://localhost:11434/v1`），数据不出本机
   - 干脆不配密钥 —— 此时 AI 按钮会提示「未配置密钥」，其余功能（文档 / 搜索 / 问题库 / 话术）**全部照常可用**
4. **语音识别同理**：选浏览器内置引擎时音频不出本机；选 Whisper 接口时音频分段上传给对应服务商

### 在生成的网页里也要写清

`06_评委问题库.md` 的「AI 使用合规」一题里，应包含一段关于这个网页自身如何用 AI 的说明，让用户被问到时能照着答。

## 七、别踩这些坑

1. **不要跳过访谈**。AI 凭空写的答辩稿，用户念出来就会被听出破绽。
2. **不要用 `\(...\)` 写公式**。渲染管线只认 `$...$` 和 `$$...$$`。
3. **不要写成书面报告**。答辩手册是**口语稿**。
4. **不要只写优点**。必须写不足——这是评委会追问的地方，提前备好答案才是手册的价值。
5. **不要交付没验收的 HTML**。用户明确要求"预览时不能有代码错误、不能有公式错误"。按 §3 阶段 6 逐项过。
6. **不要硬编码路径**。`build.js` 内部已做 `path.resolve`，但你的调用参数要传对。
