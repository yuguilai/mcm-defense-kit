# 11 份文档写作规范

逐份规范。**A 类**结构固定、填空即可；**B 类**必须按本题重写。

---

## 通用规范（全部 11 份都适用）

### 语言

- **回答栏必须是口语**。念一遍，别扭就改。
  - ❌ "本模型采用线性加权法构建综合评价函数"
  - ✅ "我们用一个加权求和把几个目标合成一个分数，权重是按重要性定的"
- **每个论点跟一个数字**。评委信数字不信形容词。
- **自称用"我们"**，不用"本文""本模型"。

### 公式

- 行内公式 `$...$`，块级公式 `$$...$$`，**独占一行**。
- 禁止 `\(...\)`、`\[...\]`。
- 表格单元格里有公式时，**公式内的 `|`（绝对值）要紧贴 `$`**：
  ```
  | 第 3 项 $\gamma\sum(|\Delta f_i|)$ | 惩罚调整幅度 |
  ```
  （解析器已对 `$...$` 内的 `|` 做保护，但别自己写成 `$ a | b $`）

### 占位符

信息缺失时，统一写：`〔待确认：此处应填 ___，请补充〕`

## A 类 · 固定骨架（5 份）

### 01_答辩流程与准备.md

**固定内容占比 ~85%**。保留全部通用清单，只改头部几处。

必含段落：
1. **形式确认三句话** —— 开场向评委确认身份/时长/是否可共享屏幕
2. **材料清单** —— 论文终稿 / 讲稿 / 速记卡 / 打印版 / 备用设备
3. **设备检查** —— 网络（有线优先，备 4G）/ 音频（麦克风 + 耳机防回声）/ 画面（分辨率、字体放大）/ 环境（光线、背景、静音）
4. **屏幕共享策略** —— 共享整个屏幕 vs 单个窗口；预先关掉微信/QQ 通知；准备"演示顺序表"
5. **常见扣分点** —— 超时、念稿、抢话、沉默超过 5 秒、答非所问

### 04_三人分工与准备清单.md

**固定内容占比 ~80%**。需要填：三人姓名、角色、负责的问题、谁主答。

必含段落：
1. **角色定义** —— 建模手 / 编程手 / 论文手 各自的答辩职责
2. **分工表** —— 谁答哪类问题（技术实现 / 模型思路 / 写作规范 / 数据来源）
3. **三份准备清单** —— 每人一份，逐项 checkbox
4. **五人协同演练** —— 完整走一遍 + 三次模拟提问
5. **现场纪律** —— 不抢答、不否定队友、卡住时如何接话
6. **每人一句话** —— 每人准备一个"我的核心贡献是……"

### 06_评委问题库.md

**27 道通用题骨架已给**，分 6.1–6.8 八组。你要做的是**给每题填具体答案**。

答题结构模板（四步）：
```
① 先给结论（一句话）
② 给依据（数字或公式）
③ 说明权衡（我们考虑过 X，但选了 Y，因为 Z）
④ 主动承认边界（这一点在 XXX 情况下确实有局限）
```

八组分类：
- 6.1 整体与创新（3 题）
- 6.2 模型与假设（4 题）
- 6.3 公式与参数（4 题）
- 6.4 数据与预处理（3 题）
- 6.5 算法与代码（4 题）
- 6.6 结果与分析（3 题）
- 6.7 检验与灵敏度（3 题）
- 6.8 局限与改进（3 题）

每题格式：
```markdown
**★★★Q1：你们这篇论文最核心的创新是什么？**

> 三条：第一，……第二，……第三，……

〔如果追问 X，就答：……〕
```

### 08_不懂代码的准备策略.md

**固定内容占比 ~90%**。分层话术保留，只需补代码入口信息。

必含段落：
1. **L1–L5 层级表** —— 从"完全不懂"到"能看懂主流程"，每层给对应的学习量和应答策略
2. **三天速成法** —— D-3 跑通代码 / D-2 看懂主函数 / D-1 记住三个关键变量
3. **万能回答模板** —— "这段的实现细节是我们的编程手负责，我说一下它对应的模型思想是……"
4. **三个保命技巧** —— 只谈输入输出 / 只谈对应公式 / 主动把问题转给编程手
5. **心态** —— 建模手不需要会写代码，评委也知道这一点

### 09_应急话术.md

**40 行话术表已给**，分 9.1–9.7 七组。只需微调称呼与队内术语。

七组：
- 9.1 被问不会的问题
- 9.2 被质疑 AI
- 9.3 被质疑代码
- 9.4 被质疑结果
- 9.5 被质疑代码与论文不一致（★最高危）
- 9.6 被质疑数据矛盾
- 9.7 技术性故障应急

格式（必须是 Markdown 表格，解析器会抽成话术卡）：
```markdown
| 情形 | 话术 |
|---|---|
| 完全不会的问题 | 这个问题我们确实没有深入考虑过，我谈一下我们的初步想法…… |
```

## B 类 · 必须重写（6 份）

### 00_总目录.md

**五分钟速览页**。评委和队友最先看这页。

必含：
1. **文件清单表** —— 11 份文件 + 一句话说明 + 建议阅读顺序
2. **核心数字**（5–8 个，带单位）
3. **一条主线** —— 一句话概括四个问题如何串起来
4. **三个创新** —— 每个一句话 + 一个支撑数字
5. **两条不足** —— 主动暴露
6. **时间分配表** —— 自述分段用时

### 02_自述讲稿.md

**最重要的一份**。约 1400–1600 字（对应 10 分钟）。

结构：
```
【开场 · 1 分钟】队号、题目、成员、一句话总结
【背景与问题 · 1 分钟】赛题要解决什么，难点在哪
【总体思路 · 1.5 分钟】主线 + 技术路线（说清四问关系）
【问题一 · 1.5 分钟】模型 + 关键公式 + 结果
【问题二 · 1.5 分钟】同上
【问题三 · 1 分钟】同上
【问题四 · 1 分钟】同上
【检验与灵敏度 · 1 分钟】怎么验证的
【创新与不足 · 0.5 分钟】三条创新 + 两条不足
```

每段必须带：
- `【动作提示】` —— 什么时候切页、什么时候停顿、什么时候看评委
- 至少一个 `$公式$`
- 至少一个具体数字

末尾附 **压缩版对照表**（8 分钟 / 6 分钟 / 4 分钟三档，标明删掉哪些段）。

### 03_公式圣经.md

**评委追问的重灾区**。每个公式回答四问。

结构：
1. **符号表** —— 全部符号 + 含义 + 单位 + 取值范围
2. **主公式逐个展开**，每个按四问写：
   - **是什么** —— 这个式子在算什么
   - **为什么** —— 为什么这么建（★评委最爱问）
   - **怎么用** —— 参数怎么定的，代码在哪
   - **注意什么** —— 前提条件 / 失效场景
3. **推导链** —— 从原始假设到最终公式的逻辑链
4. **公式 ↔ 代码对照表**（★必备）
   ```
   | 公式 | 代码位置 | 变量名 |
   |---|---|---|
   | 目标函数 $\min Z$ | `main.py:87` | `objective()` |
   ```
5. **数值代入示例** —— 挑一个简单例子手工算一遍
6. **敏感性分析** —— 参数变多少，结果变多少
7. **常见误区** —— 容易被误解的 3–5 点

### 05_代码论文不匹配应对.md

**用户最焦虑的部分**。按四类不一致分别给话术。

四类：
1. **表述不一致**（论文说"A 方法"，代码是"B 方法"但实质等价）
   → 话术：说明两者数学等价，只是叫法不同
2. **参数不一致**（论文写 α=0.5，代码里是 0.3）
   → 话术：说明这是调试后的最优值，论文里是理论取值
3. **方法不一致**（论文写解析解，代码是数值解）
   → 话术：说明这是"理论模型 + 工程实现"的正常差异
4. **结果不一致**（论文结果与代码跑出来的不同）
   → 话术：说明这是不同数据版本 / 随机种子；**这一条最危险，必须提前统一口径**

必含：
- **"不懂代码"的分层回应法** —— 按 L1–L5 层级给不同话术
- **三个文件夹** —— 交材料时的组织方式（论文 / 代码 / 结果）
- **兜底话术** —— 实在答不上来怎么收场

### 07_核心数字速记卡.md

**现场默写级别**。

必含：
1. **必背数字**（5–8 个，最大最显眼）
2. **分问题数字表** —— 每个小问的关键结果
3. **易混数字组**（5 组）—— 容易记串的数字对比
4. **权重含义** —— 目标函数里各权重代表什么
5. **稳健性数字** —— 灵敏度分析的结论数字
6. **数字话术** —— 怎么把数字说出来才有说服力
7. **默写自测表** —— 左边写指标，右边留空，自己填

### 10_三天倒计时清单.md

**D-3 → D-0 逐项 checkbox**。

```
D-3：读懂自己的论文 / 跑通代码 / 记牢核心数字
D-2：背自述稿 / 模拟提问 1 轮 / 检查设备
D-1：全流程演练 3 次 / 准备应急话术 / 打印材料
D-0：提前 30 分钟入场 / 静音检查 / 深呼吸
```

末尾附 **一张纸版**（把最关键的 10 个数字 + 3 句应急话术浓缩到 A4 一页）。
